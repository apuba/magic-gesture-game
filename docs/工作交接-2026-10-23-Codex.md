## 3. 本轮（10-22 ~ 10-23）已解决的核心问题

10-22 的「低延迟」调参之后，真机验收暴露出一个更根本的 bug：**同一只手在横屏/竖屏下被识别成不同形状**，导致横屏时手形校验把所有手判为伪手丢弃、骨架随手机转向抖动/倒置。根因是归一化坐标不是正方形（16:9 帧上 x 一单位覆盖的实体距离是 y 的近两倍），而距离/角度都直接用了归一化坐标。

本轮把「帧宽高比」贯穿整条感知链路，彻底改为**方向无关**的计算：

1. **坐标/帧变换镜像旋转修正**（`HandTrackingFrameTransform.cs`）
   - `LandmarkToGuiNormalized` 重写为：先做 `GetDisplayUv` 的两步翻转（垂直/水平），再套用旋转，移除旧的 `RotateClockwise`。
   - 新增 `verticallyMirrored` 参数；修正了 180° 横屏被塌缩到 0°、骨架倒置的问题。
   - 测试：`HandTrackingFrameTransformTests` 更新期望值，新增「竖屏翻转抵消」与「180° 半转」用例。

2. **手形校验平方距离**（`HandShapeValidator.cs`）
   - 比值改用按帧宽高比拉伸后的**平方距离**（`SquareDistance`），一套边界在横竖屏都成立（修复横屏 `wristToIndexMcp` 测得 2.2 超 1.8 上限、全盘丢弃）。
   - 下调拳/剑指等蜷曲手势的下限（上限不变继续排除侧脸）。
   - 新增 `DescribeMeasurements(hand, widthToHeight)` 输出被测比值，便于对照边界；诊断方法用 `#if DEVELOPMENT_BUILD || UNITY_EDITOR` 守卫。

3. **手指/手势分析平方方向距离**（`HandGeometry.cs`、`FingerAnalyzer.cs`、`BasicGestureClassifier.cs`、`SwordFingerDetector.cs`）
   - `HandGeometry` 新增 `SquareDistance` / `SquareDirection` / `CalculateSquarePalmWidth`：把归一化偏移的 x、z 乘以 `widthToHeight` 拉伸到正方形，关节角不再随手机朝向变化（原来同一手指在 16:9 上差约 15° 在阈值两侧跳变）。
   - `FingerAnalyzer.Analyze(hand, widthToHeight)`、`BasicGestureClassifier.Classify(hand, widthToHeight)`、`SwordFingerDetector.IsPointing(hand, widthToHeight)` 全部接收 `widthToHeight`。
   - **`IsPointing` 去掉了拇指判定**：手背朝镜头时拇指被遮挡、跟踪器在 Extended/Bent 间抖动，而它本来就不决定「是否指点」（无名指+小指已能排除张开手）。

4. **帧宽高比透传链**（`HandTrackingResult.cs`、`VisionPipeline.cs`、`MediaPipeHandTrackingProvider.cs`、`GestureRecognizer.cs`、`GestureDataRecorder.cs`、`HandTrackingDebugView.cs`）
   - `HandTrackingResult` 新增 `WidthToHeight` 字段（默认 16/9）。
   - `VisionPipeline` 把帧宽高比随结果一起发布；`GestureRecognizer`、`GestureDataRecorder` 据此分类；`HandTrackingDebugView` 把 `widthToHeight` 传入拖尾/符文更新。
   - 手形接受/拒绝日志包入 `DEVELOPMENT_BUILD` 守卫，发布构建不编译。

5. **叠加层选项精简与排版修复**（`OverlaySettings.cs`）
   - 画面帧率仅保留 30/60，跟踪帧率仅保留 10/20/30，删掉无实质收益的 45/15/25；新增 `SnapToOfferedRate` 把旧 PlayerPrefs 值就近吸附。
   - `DrawChoice` 改为先给标签固定宽度、按钮均分剩余，修复「五个选项时标签宽度为负、整行文字消失」的问题。

## 4. 关键设计约定（务必遵循，否则会重新引入方向 bug）

- **一切距离、角度、比例都必须基于「平方距离」**：归一化坐标非正方形，原始距离/角度随手机朝向变化。新增测量时直接用 `HandGeometry.SquareDistance` / `SquareDirection`，并传入 `widthToHeight`。
- **`widthToHeight` 透传链不能断**：`MediaPipe 帧 → HandTrackingResult.WidthToHeight → VisionPipeline 发布 → GestureRecognizer / BasicGestureClassifier / GestureDataRecorder / HandTrackingDebugView`。任何新增的消费方都要从 `HandTrackingResult` 取这个值，不要自己硬编码 16/9。
- **两套翻转定义必须一致**：`GetDisplayUv`（摄像头贴图翻转）与 `LandmarkToGuiNormalized`（骨架点映射）必须复用同一套「先两翻后旋转」逻辑，否则骨架与画面错位。改动其一必须同步验证另一。
- **开发期日志用 `#if DEVELOPMENT_BUILD || UNITY_EDITOR` 守卫**，避免发布构建携带诊断输出或依赖 `System.Globalization` 等仅诊断用代码。
- **`OverlaySettings` 持久化用 PlayerPrefs**：新增开关必须带版本号迁移（参考 `KeyTrackingRateVersion`），否则旧设备安装后会停在过期默认值。

## 7. 真机验收清单（HONOR ALP-AN00，`AXYP6R4A30002818`）

自动化安装成功 ≠ 视觉验收通过。必须在同一台手机上确认：

1. 横屏与竖屏下，手掌左右快速移动时骨架都连续跟随、不抖动。
2. 横屏下手形校验不再全盘丢弃（看 `rejected` 计数是否合理，而非每一帧都拒绝）。
3. 快速翻转手机（横↔竖）时骨架不倒置、不与画面错位。
4. 单指/剑指切换时轨迹不跳跃；拇指朝向相机时「指点」判定稳定。
5. 掌心（青）/指尖（橙）双色拖尾与真实手指位置重合。
6. 设置按钮文字稳定显示；关闭「显示信息文字」后 `DebugHud` 与叠加层文字都消失。
