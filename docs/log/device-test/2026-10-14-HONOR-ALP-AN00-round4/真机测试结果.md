## 附带结果

### 战斗闭环（TC-12 定性）

HUD 抓到：`Game: Result` / `Battle: Completed (1 defeated)` / `Enemy HP: 0 / 100` /
`Diag: palmFwd=198 openPalm=13 push=17 cast=7`。
注：这是自由操作下的定性证据，**没有**验证文档要求的"一次命中只结算一次""HP 不为负""死亡后不重复结算"，TC-12 仍需在正式轮量化。

### 性能线索（尚未修复）

| 场景 | HUD FPS |
|---|---|
| 权限被拒（相机未启动、无推理） | 29.9 |
| 相机 + 推理运行，**画面里有手** | **19.3** |
| 相机 + 推理运行，**画面里没手**（`Hands: 0`） | 29.9 |

结论：渲染本身能跑满 30，掉帧只发生在"检测到手"之后 —— 开销集中在 MediaPipe
检测到手后的 landmark 推理上。对应 `Assets/MagicMotion/Scripts/Vision/MediaPipeHandTrackingProvider.cs`
的 `ProcessFrame` 里同步调用 `handLandmarker.TryDetectForVideo`（CPU 委托），
且该调用发生在主线程（`CameraManager.Update` → `VisionPipeline.HandleCameraFrame` → `ProcessFrame`）。
配置侧：`visionFrameRate=15`、`cameraWidth=1280`、`cameraHeight=720`（`Resources/Config/GameConfig.json`）。

候选方案（下一轮实测后再选，不要盲改）：
- a. 配置降载：`cameraWidth/Height` 1280×720 → 960×540 或 640×480；`visionFrameRate` 15 → 12
- b. 代码改造：把推理挪出主线程（需先确认插件是否提供异步 API；本机 `PackageCache` 中未搜到 `TryDetectForVideoAsync`/`DetectForVideoAsync`）
- c. 先按 TC-13 规范实测（`gfxinfo` + 3 分钟分区），用数据决定
