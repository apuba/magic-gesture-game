## 总结论

- 结论：**阻塞（不合格）**
- P0 是否全部通过：**否**
- 主要问题：
  1. **P0 阻塞**：冷启动后应用永久停留在 `BootScene`，`Game: Boot` 状态不再变化，从未进入 `BattleScene`，因此摄像头不启动、不可交互、无任何手势/技能/战斗流程可测。TC-02 失败，TC-03 及之后全部无法执行。

## 根因分析（证据充分，供开发确认）

### 1. 直接原因：URP Asset 的噪声纹理为 null

`Assets/MagicMotion/Config/MagicMotionURP.asset` 中同时满足两个条件：

```33:34:Assets/MagicMotion/Config/MagicMotionURP.asset
  m_EnableLODCrossFade: 1
  m_LODCrossFadeDitheringType: 1
```

```82:84:Assets/MagicMotion/Config/MagicMotionURP.asset
  m_Textures:
    blueNoise64LTex: {fileID: 0}
    bayerMatrixTex: {fileID: 0}
```

`m_LODCrossFadeDitheringType: 1` 即 `BlueNoise`，URP 每帧会去读 `asset.textures.blueNoise64LTex.width`：

```1668:1677:Library/PackageCache/com.unity.render-pipelines.universal@14.0.12/Runtime/UniversalRenderPipeline.cs
            if (asset.lodCrossFadeDitheringType == LODCrossFadeDitheringType.BayerMatrix)
            {
                Shader.SetGlobalFloat(ShaderPropertyId.ditheringTextureInvSize, 1.0f / asset.textures.bayerMatrixTex.width);
                Shader.SetGlobalTexture(ShaderPropertyId.ditheringTexture, asset.textures.bayerMatrixTex);
            }
            else if (asset.lodCrossFadeDitheringType == LODCrossFadeDitheringType.BlueNoise)
            {
                Shader.SetGlobalFloat(ShaderPropertyId.ditheringTextureInvSize, 1.0f / asset.textures.blueNoise64LTex.width);
                Shader.SetGlobalTexture(ShaderPropertyId.ditheringTexture, asset.textures.blueNoise64LTex);
            }
```

两条纹理引用都是 `{fileID: 0}`（null），且运行时走 BlueNoise 分支，因此每帧抛 `NullReferenceException`，栈顶正是 `SetupPerFrameShaderConstants () [0x0009e] ... UniversalRenderPipeline.cs:1675`。

设备日志中出现的调用栈（节选）：

```text
E Unity : NullReferenceException: Object reference not set to an instance of an object.
E Unity :   at UnityEngine.Rendering.Universal.UniversalRenderPipeline.SetupPerFrameShaderConstants () [0x0009e] in ...UniversalRenderPipeline.cs:1675
E Unity :   at UnityEngine.Rendering.Universal.UniversalRenderPipeline.Render (...) [...UniversalRenderPipeline.cs:335
E Unity :   at UnityEngine.Rendering.RenderPipeline.InternalRender (...) [...RenderPipeline.cs:52
E Unity :   at UnityEngine.Rendering.RenderPipelineManager.DoRenderLoop_Internal (...)
```

补充推断（待开发在 Editor 侧确认）：URP Asset 的 `m_Textures` 在 Editor 中通常由 URP 的 Inspector/OnValidate 自动填充默认噪声纹理，而在打包后的 Player 中不存在该编辑器逻辑，于是资产中的 null 被原样加载——这解释了"Editor 里可能不报错、真机每帧报错"的现象。

### 2. 后果链：协程被异常卡死，BootScene 永不切换

```66:81:Assets/MagicMotion/Scripts/Core/ExperienceFlowController.cs
        private IEnumerator EnterMvpBattle()
        {
            // Let all persistent systems finish Start before replacing BootScene.
            yield return null;

            var operation = SceneManager.LoadSceneAsync("BattleScene", LoadSceneMode.Single);
```

`ApplyScene("BootScene")` 在 `Start()`（19:47:56.899）里启动该协程，协程在 `yield return null` 处等待下一帧；而下一帧（19:47:56.931）渲染阶段即抛异常，帧被中断，协程再未恢复，`LoadSceneAsync("BattleScene")` 从未被调用，`GameState` 永远停在 `Boot`。

因此链路是：**渲染每帧异常 → BootScene 协程不恢复 → 不加载 BattleScene → `CameraManager.StartCamera()` 不被调用（所以没有权限请求、没有相机帧）→ 无手势/动作/技能/战斗可行 → 除 TC-00/TC-01 外全部测试项不可执行。**

佐证：日志中不存在 `Failed to enter the MVP battle scene.`，也不存在 `Scene 'BattleScene' couldn't be loaded`；`ProjectSettings/EditorBuildSettings.asset` 中 BootScene/TrainingScene/BattleScene 均为 `enabled: 1`，说明 BattleScene 已在构建内，卡点不在构建配置，而在异常把帧与协程一起打断。

### 3. 建议修复方向（需在 Editor 验证后重新打包复测）

按稳妥程度排序：

1. **重新生成 URP Asset**：删除 `Assets/MagicMotion/Config/MagicMotionURP.asset`，用 `Assets → Create → Rendering → URP Asset (with Universal Renderer)` 重建（新资产会自带 blueNoise64LTex / bayerMatrixTex），再把 `ProjectSettings/GraphicsSettings.asset` 的 `m_CustomRenderPipeline` 与 QualitySettings 对应级别重新指回新资产。
2. **只改该资产**：将 `LOD Cross Fade Dithering Type` 改为 `Bayer Matrix`（或关闭 LOD Cross Fade），并把 `m_Textures` 的两条引用补上 URP 包内默认纹理。
3. **兜底防御**：`EnterMvpBattle()` 增加异常保护与超时日志（例如 try/catch + `Debug.LogError`），保证"场景切换失败"能被日志直接观测，而不是表现成静默卡死；同时对渲染异常建议在 CI/真机冒烟中加入"日志中不得出现 `SetupPerFrameShaderConstants` 异常"的门禁。
4. 修复后必须重跑：TC-02 → TC-03 → TC-04（这些是本次阻塞的 P0 链条），再按 TC-05 ~ TC-14 全量复测。

## 最终建议

- 是否允许进入下一阶段：**不允许**（P0 阻塞未解除前，任何手势/技能/战斗结论都不成立）
- 必须先修复的问题：
  1. 修复 `MagicMotionURP.asset` 缺失的噪声纹理（或重建 URP Asset），消除每帧 `SetupPerFrameShaderConstants` 异常；
  2. 确认修复后 BootScene 能自动进入 BattleScene（`Game: Battle`、`Camera: Running`）；
  3. 为场景切换协程补异常/超时保护，避免同类问题再次表现成"静默黑屏卡死"。
- 建议优化项：
  1. 真机冒烟测试加入日志门禁：`FATAL EXCEPTION / ANR / SIGSEGV / SetupPerFrameShaderConstants 异常` 出现任一即判失败；
  2. `DebugHud` 增加一帧"渲染异常次数"计数，便于现场一眼判定渲染管线是否健康；
  3. 摄像头权限建议在进入场景前（或首次启动时）就请求，避免"场景没进去 → 权限从没弹过"的排查困境；
  4. 环境侧建议固定使用与设备 adbd 兼容的 platform-tools 版本，或统一走 USB，避免无线调试的协议不兼容干扰验收。
- 修复完成后需要重跑的测试范围：TC-02、TC-03、TC-04 必须通过，随后按 TC-05 ~ TC-14 全量执行（本文档第 8 节）。
