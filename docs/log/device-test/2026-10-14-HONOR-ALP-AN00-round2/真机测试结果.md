## 根因（与第一轮一致，且本轮已核对工程文件未修复）

### 1. URP 资产的噪声纹理仍为 null

`Assets/MagicMotion/Config/MagicMotionURP.asset`（本轮 19:45:01 被重新序列化，但引用未变）：

```33:34:Assets/MagicMotion/Config/MagicMotionURP.asset
  m_EnableLODCrossFade: 1
  m_LODCrossFadeDitheringType: 1
```

```82:84:Assets/MagicMotion/Config/MagicMotionURP.asset
  m_Textures:
    blueNoise64LTex: {fileID: 0}
    bayerMatrixTex: {fileID: 0}
```

URP 每帧执行：

```1673:1677:Library/PackageCache/com.unity.render-pipelines.universal@14.0.12/Runtime/UniversalRenderPipeline.cs
            else if (asset.lodCrossFadeDitheringType == LODCrossFadeDitheringType.BlueNoise)
            {
                Shader.SetGlobalFloat(ShaderPropertyId.ditheringTextureInvSize, 1.0f / asset.textures.blueNoise64LTex.width);
                Shader.SetGlobalTexture(ShaderPropertyId.ditheringTexture, asset.textures.blueNoise64LTex);
            }
```

`asset.textures.blueNoise64LTex` 为 null → 每帧 `NullReferenceException`（设备日志栈顶固定为 `UniversalRenderPipeline.cs:1675`）。

**重要补充（本轮新确认）**：仅把 `m_EnableLODCrossFade` 关掉**不能**规避该异常。URP 的属性实现不判断该开关：

```1091:1094:Library/PackageCache/com.unity.render-pipelines.universal@14.0.12/Runtime/Data/UniversalRenderPipelineAsset.cs
        public LODCrossFadeDitheringType lodCrossFadeDitheringType
        {
            get { return m_LODCrossFadeDitheringType; }
        }
```

也就是说，只要 `m_LODCrossFadeDitheringType` 为 1（BlueNoise）或 0（BayerMatrix），都会去读对应纹理；**必须把两条纹理引用真正补上**（或重建 URP 资产），才能消除异常。

### 2. 后果链：协程不恢复 → 场景永不切换

```66:81:Assets/MagicMotion/Scripts/Core/ExperienceFlowController.cs
        private IEnumerator EnterMvpBattle()
        {
            // Let all persistent systems finish Start before replacing BootScene.
            yield return null;

            var operation = SceneManager.LoadSceneAsync("BattleScene", LoadSceneMode.Single);
```

`Start()`（19:53:29.839）启动该协程 → 协程在 `yield return null` 等待下一帧 → 下一帧（19:53:29.873）渲染阶段抛异常、帧被中断 → 协程不再恢复 → `LoadSceneAsync("BattleScene")` 从未执行 → `GameManager` 永远停在 `Boot` → `CameraManager.StartCamera()` 从未被调用（无权限请求、无相机帧）→ 手势/动作/技能/战斗全部不可能发生。

日志侧佐证：既无 `[MagicMotion] Failed to enter the MVP battle scene.`，也无 `Scene 'BattleScene' couldn't be loaded`；`ProjectSettings/EditorBuildSettings.asset` 中 BootScene/TrainingScene/BattleScene 均 `enabled: 1`。卡点不在构建配置。

## 建议修复（本轮已定位到可直接落地的补丁）

在 `Assets/MagicMotion/Config/MagicMotionURP.asset` 中把两处 null 引用替换为 URP 包自带的默认纹理（GUID 已核对为本机 URP 14.0.12 包内实际 GUID）：

```yaml
  m_Textures:
    blueNoise64LTex: {fileID: 2800000, guid: e3d24661c1e055f45a7560c033dbb837, type: 3}   # Textures/BlueNoise64/L/LDR_LLL1_0.png
    bayerMatrixTex:  {fileID: 2800000, guid: f9ee4ed84c1d10c49aabb9b210b0fc44, type: 3}   # Textures/BayerMatrix.png
```

（等价做法：在 Editor 里删除该资产后用 `Assets → Create → Rendering → URP Asset (with Universal Renderer)` 重建，再把 `ProjectSettings/GraphicsSettings.asset` 的 `m_CustomRenderPipeline` 与 QualitySettings 对应级别指回新资产。）

另外建议（不阻塞验收但必须补）：
1. `EnterMvpBattle()` 增加 try/catch 与超时日志，让"场景切换失败"能被日志直接观测，而不是表现成静默黑屏；
2. 真机冒烟加日志门禁：出现 `FATAL EXCEPTION / ANR / SIGSEGV / SetupPerFrameShaderConstants 异常` 任一即判失败；
3. 摄像头权限提前到启动时请求，避免"场景没进去 → 权限从没弹过"的排查盲区。

修复后需重跑：TC-02 → TC-03 → TC-04（P0 链条），通过后再执行 TC-05 ~ TC-14。
