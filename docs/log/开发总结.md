## 三、开发期间修复的问题

1. Unity 工程缺少内置 Audio 模块，导致 `WebCamTexture` 和 `WebCamDevice` 无法解析；已补充 `com.unity.modules.audio`。
2. MediaPipe 资源管理依赖 AssetBundle 与 UnityWebRequest；已补充对应 Unity 内置模块。
3. 编辑器程序集缺少 URP Runtime 引用；已补充 `Unity.RenderPipelines.Universal.Runtime`。
4. 项目命名空间 `MagicMotion.Camera` 与 `UnityEngine.Camera` 产生名称冲突；已使用完整类型名消除冲突。
5. NUnit 版本不支持原有异常断言简写；已改为显式异常类型断言。
6. Android 工具不接受包含中文的项目路径；构建时使用临时 ASCII 盘符映射，构建完成后立即移除，不复制项目。
7. Unity Hub 不会自动登记通过编辑器命令行打开的工程；已通过 Unity 项目注册命令加入 Hub 项目列表。
8. Unity Android 安装最初缺少版本化 OpenJDK 模块；已安装并验证 OpenJDK 11.0.14.1。

# 2026-10-20 手部轨迹与剑指画符验证开发总结

## 一、本次开发目标

本次开发在当前有效工程 `E:\2026\MagicMotion` 中实现独立的手部追踪表现验证层，目标是验证以下交互是否可行：

1. 普通手部移动时，使用手心中心生成短时流星拖尾。
2. 单手做出双指剑指并稳定悬停后自动起笔。
3. 起笔后使用食指尖与中指尖的中点记录画符轨迹。
4. 解除剑指或持续丢失手部时自动收笔。

本次功能复用现有 `HandTrackingResult` 和 21 点 MediaPipe 识别结果，不创建第二套 Hand Landmarker，也不改变现有 `OPEN_PALM + FORWARD + PUSH → SK001 震山掌` 战斗链路。

## 二、交互规则

### 1. 普通手心轨迹

- 轨迹锚点：`HandGeometry.CalculatePalmCenter`。
- 轨迹颜色：蓝青色。
- 轨迹生命周期：约 `0.65` 秒。
- 最小采样距离：归一化坐标 `0.01`，小于该距离的抖动不加入轨迹。
- 旧轨迹点按时间逐渐变细、变透明并自动移除。

### 2. 剑指判定

剑指需要同时满足：

- 食指伸直。
- 中指伸直。
- 无名指收拢。
- 小指收拢。
- 拇指不能处于伸直状态。
- 食指尖与中指尖的距离不超过掌宽的 `0.42` 倍。

剑指笔锋点计算方式：

```text
SwordFingerPoint = (IndexTip + MiddleTip) / 2
```

### 3. 悬停起笔与收笔

状态机为：

```text
Idle
→ SwordFingerCandidate
→ Drawing
→ StrokeEnd
→ Idle
```

- 检测到剑指后进入候选状态。
- 剑指保持低速稳定 `1.0` 秒后自动进入 `Drawing`，不需要向前轻点。
- 候选期间笔锋移动超过掌宽的 `0.30` 倍，会重新计算悬停时间。
- 候选点以金色圆点显示，并通过 HUD 显示悬停进度。
- 画符笔迹使用金色粗线显示。
- 识别短暂中断时保留 `0.20` 秒容错，避免单帧丢失造成断笔。
- 超过容错时间仍未恢复剑指则收笔。
- 完成的笔迹保留约 `1.5` 秒后自动清除。
