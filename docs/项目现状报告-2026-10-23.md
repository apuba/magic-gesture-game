## 一、项目定位

Magic Motion 是一个基于 Unity 和 MediaPipe 的 Android 体感魔法游戏 MVP。玩家通过前置摄像头完成手势识别，触发技能并攻击场景中的石魔。

当前已形成的核心链路是：

```text
前置摄像头 → MediaPipe 手部关键点 → OpenPalm
→ Forward 掌心方向 → Push 推掌 → SK001「震山掌」
→ 黄色魔法弹体 → 命中石魔并扣血
```

当前唯一有效工程目录为 `E:\2026\MagicMotion`。旧中文目录和 junction 副本不再作为构建源。

## 四、手势识别现状

### 当前支持的玩法手势

| 环节 | 当前实现 |
|---|---|
| 手势 | `OpenPalm` |
| 掌心方向 | `Forward` |
| 动作 | `Push` |
| 技能 | `SK001 震山掌` |
| 最低技能置信度 | `0.78` |
| 输入最大年龄 | `0.25 s` |

### 当前可靠范围

- 主要有效距离：约 `0.5～0.8 m`。
- 约 1 m 及以上距离不作为可靠识别范围。
- 远距离宽松阈值曾产生误触和重复触发，因此已回退，不再继续降低门槛。

### 已解决的关键问题

- 横屏/竖屏下同一只手被识别成不同形状的问题。
- 非正方形归一化坐标导致的距离和角度漂移。
- 180° 横屏坐标塌缩、骨架倒置和镜像错位。
- 横屏手形校验过严导致整帧被拒绝。
- 设置面板选项标签消失和中文字体初始化为空。
- DebugHud 重复绘制摄像头造成的画中画。
- 跟踪频率设置未真正作用于 VisionPipeline 的问题。

## 六、当前主要风险

1. 识别稳定性主要在同一台设备和有限样本上得到，跨用户、跨设备泛化尚未充分验证。
2. 当前缺少独立验证集，存在对已调参数过拟合的可能。
3. 左手、双手、快速旋转和复杂背景仍需系统化覆盖。
4. 长时间运行的性能、温升和内存稳定性尚未形成完整数据。
5. Unity Licensing Client 仍可能出现 token/ULF 过期提示，正式发布前需处理。
6. `MediaPipeHandTrackingProvider.gpuActive` 仍存在未使用字段警告。
7. APK 体积约 99 MB，仍有进一步分析和压缩空间。

## 七、建议的后续顺序

### P0：建立独立回归验证

- 使用未参与标定的新动作建立正例和负例集合。
- 统计识别率、漏识别、误触发、重复触发和响应延迟。
- 将代表性样本保存为后续自动回放基线。

### P1：补齐覆盖范围

- 左手快速验证，必要时完成完整左手采集。
- 双手识别与遮挡场景。
- 横竖屏、镜像、180° 旋转和不同距离。

### P1：性能与稳定性

- 记录跟踪 FPS、显示 FPS、结果年龄、掉帧和内存。
- 连续运行至少 15 分钟，记录是否出现识别逐渐变差或 UI 卡顿。

### P2：玩法产品化

- 完善技能释放反馈、音效、震动和失败提示。
- 完善战斗重置、冷却和状态反馈。
- 在识别基线不变的前提下扩展第二个技能或训练流程。

## 八、当前结论

Magic Motion 的核心手势施法链路已经可用，方向无关化和当前识别基线已经冻结。项目目前最重要的工作不是继续凭体感调阈值，而是用独立数据和长期运行数据证明当前稳定性，再在稳定契约上扩展玩法和产品体验。
