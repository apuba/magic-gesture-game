## 0. 交付目的与边界

本文件面向 Codex / CodeBuddy、Unity 开发、UI / VFX 美术、测试人员。目标是在**不破坏既有震山掌链路**的前提下，新增长序列符文施法玩法，以及一致的中式玄幻符箓美术表现。本文为设计与验收依据，**不代表新功能已实现**。

已确认玩法原则：第一人称施法；剑指手背起手、翻至手心召符；符文在剑指指尖前生成且持续跟手；上下左右选择雷火水风；元素选定后锁定并待命；切张掌后通过 Push 释放。

## 2. 核心玩法（确认版）

### 2.1 五阶段、六步骤

**起手姿态 → 翻掌召符 → 方向选符 → 符文待命 → 推掌释放**

| 步骤 | 玩家操作 | 系统结果 | 确认状态 |
|---|---|---|---|
| 1 | 结剑指，**手背朝向屏幕 / 摄像头** | 识别起手候选 | 已确认 |
| 2 | 保持剑指，翻转至**手心朝向屏幕 / 摄像头** | 完成有序翻掌序列 | 已确认 |
| 3 | 翻掌成功 | 在剑指双指指尖前方生成**基础符文** | 已确认 |
| 4 | 保持剑指，向上 / 下 / 左 / 右移动 | 将基础符文转化为四系之一 | 已确认 |
| 5 | 元素成型并锁定 | 元素符文在指尖前持续跟随、悬浮待命 | 已确认 |
| 6 | 由剑指切换张掌并向前推掌 | 从掌前释放对应元素攻击 | 已确认 |

### 2.2 四系映射（固定）

| 剑指位移 | 元素 | 符文名称 | 释放结果 | 推荐技能 ID（新增、待与项目注册表核对） |
|---|---|---|---|---|
| ↑ 上 | 雷 | 雷符 | 雷击 / 电束 | `SK101` |
| ↓ 下 | 火 | 火符 | 火球 / 爆燃 | `SK102` |
| ← 左 | 水 | 水符 | 水刃 / 水流箭 | `SK103` |
| → 右 | 风 | 风符 | 风刃 / 空气冲击 | `SK104` |

**方向是手部在画面里的位移方向，不是双指指向；屏幕镜像 / 左右翻转必须在坐标统一层处理后再识别。**

**不可变四方向规则（后续实现不得改动）：**

| 屏幕方向 | 属性符箓 | 视觉表现 |
|---|---|---|
| ↑ 上 | 雷符 | 雷击 / 电流束，高爆发与短暂硬直视觉 |
| ↓ 下 | 火符 | 火球，小范围爆燃视觉 |
| ← 左 | 水符 | 水刃 / 水流箭，流体冲击视觉 |
| → 右 | 风符 | 风刃 / 空气冲击，高速切割和轻击退视觉 |

法阵节点必须始终按上述屏幕方向固定排列：上雷、下火、左水、右风；横竖屏只调整符图朝向，不得改变节点的屏幕方向归属。

### 2.3 符文位置（固定）

- 基础符文在**食指和中指合并的指尖前方**出现，不贴住手指，也不过远。
- 基础符文在选择阶段跟随剑指移动；法阵圆盘与四个属性节点在出现时锁定中心，不再随手移动。
- 方向确认后，元素符锁定；双指状态下符箓跟随双指，张掌状态下符箓平滑移动到手心。双指与张掌均属于有效持符姿态。
- 方向确认后只锁定**元素类型**，不锁定符文位置。
- 双指与张掌之间可往返切换，符箓在指尖与手心锚点之间平滑切换；只有有效 Push 才真正发射。
- MVP 同时仅容许一张待命符文，不叠加、不连选、不做斜向技能。

## 3. 手势识别与交互判定

### 3.1 剑指 `SwordFinger`

食指和中指伸直且彼此靠近；无名指、小指收拢；拇指自然收拢或贴近弯曲指侧。允许生理差异、轻微张开和半弯误差。输出建议：`gesture= SwordFinger`、`gestureConfidence`。剑指姿态判定不得只依赖二维像素距离，应使用已修正宽高比 / 方向的关键点及相对掌宽尺度。

### 3.2 朝向 `HandFacing`

分类输出：`BackFacingCamera`、`PalmFacingCamera`、`Side`、`Unknown`，附 `facingConfidence`。判定需考虑左右手的掌面法线符号差异、镜像及相机旋转。靠近侧视角、深度信息不可靠或关键点抖动时返回 `Unknown`，而不是强行定正反。

### 3.3 有序翻掌 `FlipBackToPalm`

必须是**同一只被持续跟踪的手**按时序经历：

`SwordFinger + Back`（稳定） → 允许短暂 `Side / Unknown` → `SwordFinger + Palm`（稳定） → `FlipSuccess`

禁止仅凭最后一帧“手心剑指”直接召符。翻转过程中允许短暂跟踪波动，但丢手时间超过容错门槛须取消；同帧不得多次召符。成功时才生成基础符文和位移锚点。

### 3.4 四向位移 `DirectionSelection`

1. 仅在 `BaseRuneReady` 时检测；锚点取**基础符文生成时**的经屏幕旋转和镜像统一后的指尖双点中点（可测试与掌中心混合追踪以降低抖动）。
2. 实时位置 `p` 与锚点 `a` 计算 `dx=p.x-a.x`、`dy=p.y-a.y`，其中建议屏幕坐标 `+x=右`、`+y=下`。
3. 使用**同一尺度**计算水平 / 垂直位移：建议将坐标转换为等比例屏幕空间后，再将差值除以短边长度，避免非正方形归一化坐标的比例失真。
4. 建议判定：上 `dy < -D 且 |dy| > r|dx|`；下 `dy > D 且 |dy| > r|dx|`；左 `dx < -D 且 |dx| > r|dy|`；右 `dx > D 且 |dx| > r|dy|`。
5. 方向成立后短时稳定确认，一次成功即锁定；不得在 RuneReady 阶段重复选符。
6. 方向阶段持续要求剑指；暂时分类波动允许短暂宽限，避免一帧误失造成频繁取消。

**开发试验参数（非既有基线、需要真机标定）：**

| 参数 | 建议初值 / 范围 | 说明 |
|---|---|---|
| 剑指起手稳定 | 0.3 s（试验 0.25–0.4 s） | 对误触 / 延迟综合评估 |
| 剑指置信度 | 0.80 | 新分类器建议值 |
| 朝向置信度 | 0.75 | 遇模糊面向返回 Unknown |
| 翻掌时限 | 1.2 s（试验 0.2–1.2 s） | 从起手成功计时 |
| 翻掌终点稳定 | 0.2 s（试验 0.15–0.25 s） | 避免快速晃动误触发 |
| 方向窗口 | 1.2 s | 基础符文生成后计时 |
| 方向距离 `D` | 屏幕短边 `15%`（试验 12–18%） | 使用比例一致的屏幕空间 |
| 主轴系数 `r` | `1.25`（试验 1.2–1.5） | 过滤斜向误判 |
| 方向稳定确认 | 约 `0.1 s`（试验 0.08–0.15 s） | 应以时间为主，不依赖固定 FPS 的 3–5 帧 |
| 选择 / 持符最长时间 | `10 s` | 双指与张掌共享同一待命窗口，超时消散 |
| 释放后冷却 | `0.4–0.8 s` | 遵循现有 Push 冷却 / 收回重置机制，避免叠加冲突 |

### 3.5 待命与 Push

- 待命符文持续跟手，允许手部轻微晃动；**不得因选符后的额外平移而改变元素**。
- 检测到剑指切张掌时，表现上允许符文过渡到掌前；切掌动作本身**不算释放**。
- 元素锁定后，双指和张掌均可继续持有符文；张掌将符文移到手心，重新双指则移回指尖。
- 双指或张掌状态下均可识别有效 Push；复用既有 `OpenPalm + Forward + Push` 路由与收回重置，作为元素技能释放事件。
- 待命时有效 Push 优先消耗当前符文并释放元素法术；无待命符文时仍按旧逻辑触发 `SK001 震山掌`。
- 若符文施法过程中出现 Push 或张掌，是否允许触发 SK001 需由**互斥路由**处理：建议符文流程开始后暂时屏蔽 SK001，避免一次动作释放双技能；流程取消并恢复 Idle 后再恢复 SK001。

## 4. 状态机与事件契约

```text
Idle
  └─ SwordFinger + Back 稳定 → SwordReady
SwordReady
  └─ 开始有序翻掌 → Flipping
Flipping
  └─ SwordFinger + Palm 稳定 → BaseRuneReady  [生成符文 / 记录锚点]
BaseRuneReady
  └─ 四方向确认 → RuneReady(element) [转元素 / 锁定]
RuneReady
  ├─ 张掌 → Releasing [符文移至手心，仍可持有]
  └─ 有效 Push → Casting [消耗符文 / 释放技能]
Releasing
  ├─ 双指 → RuneReady [符文移回指尖，仍可持有]
  └─ 有效 Push → Casting [消耗符文 / 释放技能]
Casting → Cooldown → Idle

SwordReady / Flipping / BaseRuneReady / RuneReady
  └─ 超时 / 超容忍丢手 / 取消 → Cancelled → Idle
```

> 可在内部另设 `ElementSelected` 瞬时事件用于触发变色动画，但无需强制将其做成等待状态。

**关键事件（建议命名）：**

- `SwordPoseAcquired(handId)`
- `FlipCompleted(handId)`
- `BaseRuneSummoned(handId, anchorPosition)`
- `RuneElementSelected(handId, element)`
- `RuneReady(handId, element, expiresAt)`
- `RuneCast(handId, element)`
- `RuneCancelled(handId, reason)`

同一次召符会话必须使用唯一 `castSessionId`、手 ID 和单次消费标志，防止多帧重入、左右手串帧和重复发弹体。超时使用单调时间 / 帧时间戳；丢手、超时、重置均清理锚点、符文对象和路由状态。

## 5. 战斗技能表现

| 技能 | 召符元素 | 掌前释放 | 弹道 | 命中石魔 | MVP 战斗目标 |
|---|---|---|---|---|---|
| 雷符 | 蓝紫电弧 | 符纹收束为电能核心 | 雷击束 / 电流脉冲 | 闪白、电流爬身、短硬直感 | 快速、单体强反馈 |
| 火符 | 赤红燃光 | 符纸卷缩成火球核心 | 火球带火尾 | 火焰爆开、火星、灼烧感 | 明确的爆燃反馈 |
| 水符 | 青蓝流纹 | 凝练成水刃核心 | 水刃 / 水流箭 | 水花、涟漪、冲击 | 稳定的水系攻击 |
| 风符 | 翠绿气旋 | 聚为风刃核心 | 高速风刃 / 空气波 | 切裂风痕、扬尘、轻击退 | 轻快的风系攻击 |

**MVP 取舍：**四系先完成可辨识的不同释放与命中视觉；伤害可暂用同一数值，雷系硬直、火系持续灼烧、水系减速、风系击退等复杂状态先作为扩展方向，不作为第一批验收硬指标。

## 6. UI / 美术视觉总规范

### 6.1 美术定位

**中式玄幻 / 道术纸符 / 第一人称魔法手势战斗。** 参考用户给出的传统符箓与灵力火焰感：核心形象为**细长黄纸符本体、中央书写符纹、元素发光与周边粒子**，而不是大型西式圆形魔法阵。画面中以玩家第一人称的**手背、手心、部分前臂**及石魔为主，避免第三人称施法者抢占画面。

### 6.2 统一符纸结构

1. **本体：**长条形米黄 / 黄符纸，略带纤维和旧纸肌理，边缘自然但轮廓清楚。
2. **符字：**原创的可读性强的中式符纹形状，中央纵向构图；避免直接将普通文字替代整张符箓设计。
3. **元素层：**元素色发光笔迹 + 细微边缘光晕 + 小范围元素粒子；不过度遮住纸符本体。
4. **动态层：**漂浮微摆、轻微呼吸光、移动拖尾、释放时收束。
5. **尺寸与遮挡：**保证手机游戏画面中可辨识且不遮住石魔关键命中区域；具体世界尺寸和屏幕占比需在真实机型上调试。

## 7. HUD 与交互提示

**战斗 HUD 原则：**少而清楚，优先展示手、符和石魔；调试信息在 Debug 模式显示，正式游戏隐藏大段诊断文字。

- **底部中央：**轻量五阶段进度：`剑指 → 翻掌 → 选符 → 待命 → 推掌`；当前步骤高亮。
- **手指近旁：**基础符纸与元素符纸为主要视觉反馈；选符期间显示四向小提示 `↑ 雷 / ↓ 火 / ← 水 / → 风`，成功后自动淡出。
- **待命提示：**`雷符已就绪 · 推掌释放` 等，允许以小型倒计时 / 消散脉冲表示 4 秒窗口。
- **火符转换 VFX：**空白符转为火符时，必须同时播放火焰核心、外层火焰、火星与柔光 Sprite Sheet / 贴图层；中央符箓本体淡入与火焰强度同步，不能只用静态贴图替换。火焰层必须绘制在符箓本体上方，火符与火焰整体相对法阵中心上移 20sp，法阵中心及其他属性节点不移动。
- **失败提示：**`请保持剑指`、`翻掌未完成`、`选符失败`、`符文已消散`，轻反馈不长期遮挡画面。
- **战斗 HUD：**保留目标石魔血条 / 状态等现有信息，不因新系统整体重做。

- VFX 交付：粒子、Shader 参数、材质配置、动画节奏说明；移动端优先减少过度绘制和高成本透明叠加。
- 资源需注明画幅、透明度、命名、尺寸、色彩空间、Pivot 和 World-space Billboard / 朝向镜头策略；最终分辨率、特效粒子预算以设备测试确定。

## 8. 推荐代码职责边界

| 建议模块 | 责任 | 重要约束 |
|---|---|---|
| `SwordFingerDetector` | 剑指分类 | 不直接释放技能 |

## 11. 待验证与实施时不得擅自视为定论的事项

1. 所有新增识别阈值及超时参数均为**候选初值**，不等于当前工程已有参数，也尚未真机验收。
2. 符文在 3D 世界相对于指尖的具体距离、朝向与缩放曲线待实机 UI / 视觉调试；必须保证视觉上的“指尖前方持续跟手”。
3. 方向锚点采用双指指尖中点为第一候选，允许以真机证据比较手掌中心 / 混合方案的抖动表现；改动不能影响对用户已确认的动作映射。
4. `SK101–SK104` 为建议编号，需与现有技能注册 / 资源 ID 核对后固定。
5. 允许短暂误判 / 丢帧的时长、双指与张掌切换的平滑时间、Push 的有效窗口、现有冷却与新冷却的衔接需结合真机证据继续确定。
6. 双手完整识别、左手全量测试、独立样本泛化与长时间性能测试目前尚未完成。
7. 四系技能的属性差异（灼烧、硬直、减速、击退）是后续平衡方向；MVP 首先验证**区别清楚的视觉、可释放、可命中**。

## 12. 最终交付验收定义

符文玩法应满足：玩家**手背剑指起手** → **同手翻到手心** → **指尖前召唤基础符** → **保持剑指向四向移动并正确选中雷火水风** → **双指或张掌持有元素符** → **张掌时符箓移到手心、双指时回到指尖** → **双指或张掌状态下 Push，从当前锚点释放对应攻击** → **石魔受击**。全程无重复施法、无双技能并发，并保留普通 `SK001 震山掌` 可用。视觉以**黄纸实体符箓 + 发光符纹 + 第一人称法术**为核心，不能替换成大面积西式魔法阵方案。
